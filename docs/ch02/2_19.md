# 2.19 `@ap[1],[2]`：オートポルタメント

[← 目次](../index.md)

## 【記述例】

```mml
#MB:PITCH_SCALE ps=1 {
   type = 12_TET,
   base_note = 57,
   base_freq = 440.0,
   halftone_reso = 100,
   auto_portamento = linear_duration,
}
ps1 t120 l4 v15 @@"pls"
@ap100,36 cdefgab>c
@apz cdefgab>c;
```

上記の場合、前半の音符は、直前に鳴っていた音符の音程から 100msec かけて滑りながら発音します。（最初の音符の「直前」の音程番号は36）  
`@apz` 以降は滑らなくなります。

## 【解説】

オートポルタメントです。  
音符を並べるだけで、直前に鳴った音符の音程から、いま鳴らす音符の音程へ、自動的に滑らかに変化させます。

ポルタメント（`_`）とは異なり、音名を記号で繋ぐ必要がありません。一度指定すると、次に指定し直すまで、以降のすべての音符に効きます。

オートポルタメントを使用するには、あらかじめ、ピッチスケール定義（`#MB:PITCH_SCALE`）で、変化のさせ方の型を宣言しておく必要があります。

---

## 【宣言】ピッチスケール定義の `auto_portamento`

```mml
#MB:PITCH_SCALE ps=定義番号 {
   type = 12_TET,
   ：
   auto_portamento = [型名],
}
```

`auto_portamento` を記述できるのは、`type` が次の２つの場合だけです。

- `type = 12_TET`
- `type = 12_TET_trunc`

これ以外の `type`（`f_number` 系、`divrate` 系、`steprate` 系）の定義に `auto_portamento` を書くと、項目名のエラーになります。  
また、これらの `type` を選んでいるトラックで `@ap` を記述すると、エラーになります。

`auto_portamento` を書かなかった場合、および `#MB:PITCH_SCALE` を１つも書かなかった場合は、`auto_portamento = linear_duration` が指定されたものとみなされます。

[（ピッチスケール定義とは）](2_13n14.md)

---

### 型名の一覧：

|型名|変化のカーブ|引数[1] の意味|
|:-|:-|:-|
|`linear_duration`|直線|到達までの時間|
|`linear_duration_per_oct`|直線|１オクターブあたりの時間|
|`root2nd_duration`|平方根カーブ|到達までの時間|
|`pow2nd_duration`|２乗カーブ|到達までの時間|
|`sys2lv`|特定機種(type:sys2lv)互換の漸化式|特定機種での引数（後述）|
|`sys22rr`|特定機種(type:sys22rr)互換の漸化式|256 − 特定機種での速度（後述）|

- `linear_duration_per_oct` は、音程差に比例して所要時間が決まるため、実質的に「変化率が一定」の指定になります。音程差の大小によらず、単位時間あたりの変化量が同じになります。
- `root2nd_duration` / `pow2nd_duration` に、`_per_oct` の型はありません。
- `sys2lv` は、特定機種(type:sys2lv)の動作を再現する型です。時間で指定する４つの型とは仕様が大きく異なります。（後述）
- `sys22rr` は、別の特定機種(type:sys22rr)の動作を再現する型です。`sys2lv` と同じ仕組みで、下降の速さとスラーの扱いが異なります。（後述）

## 【コマンド】

```mml
@ap[1],[2]      引数[1] を、型の既定単位（msec）で解釈します
@ap%[1],[2]     引数[1] を、tickカウント数で解釈します
@apz            オートポルタメントを停止します（初期設定）
```

`@ap` はトラックの状態です。一度指定すると、次に指定し直すまで、以降のすべての音符に効きます。  
トラック先頭における初期設定は、`@apz`（停止）です。

`@ap`コマンドは時間を消費しません。音符の位置や長さには、一切影響しません。

---

### 引数[1]（数値1）：

変化の速さを指定します。意味と単位は、宣言した型と、`%` の有無で決まります。

- `@ap` の場合は、型の既定単位で解釈されます。`sys2lv`・`sys22rr` 以外の４つの型では、単位は msec です。
- `@ap%` の場合は、tickカウント数で解釈されます。

小数点以下の指定も受け付けます。`@ap` と `@ap%` のどちらでも同じです。

```mml
@ap12.5   @ap0.75   @ap%0.5   @ap%8.25
```

引数[1] は省略できません。省略すると、次の警告が出てコンパイルが止まります。

```
@ap[],[] の数値1 は省略できません。
```

※`@ap 100` のように、コマンド名と数値の間にスペースを置くことは出来ません。省略として扱われます。

---

### 引数[2]（始点の音程番号）：

`@ap` を記述した直後の音符に限り、変化の開始音程を差し替えます。  
引数[2] はカンマで区切って指定します。省略できます。

|指定値|動作|
|:-:|:-|
|省略、または負数|差し替えません。それまで記憶している音程から滑ります|
|0 〜 119|`@ap` 直後の音符だけ、指定の音程番号から滑ります|

差し替えは１音で使い切ります。２音目以降は、通常どおり直前に鳴った音符が始点になります。

指定した音程番号には、その時点の `@d`（デチューン）の設定値が加算されます。音程番号が、音階とデチューンの複合値であるためです。

[（音程番号とは）](2_6.md)

---

### 停止：

次の３つは、いずれも同じ「停止」の意味になります。

```mml
@apz        @ap0        @ap%0
```

引数[1] が ０以下 のときは、すべて停止として扱われます（`@ap-1`、`@ap%-5` なども同じ）。

停止は「その音符だけ滑らない」ではなく、「以降のすべての音符が滑らなくなる」という意味です。再び滑らせるには、`@ap` を記述し直します。

---

### `%` を指定できない場合：

次の２つは、いずれもエラーになります。

|記述|理由|
|:-|:-|
|`@apz%`|停止に単位はありません|
|`@ap%`（型が 特定機種互換の `sys2lv`・`sys22rr` のとき）|特定機種の 引数[1] は時間ではないためです|

---

## 【動作】

### 始点の記憶：

「直前に鳴った音符の音程番号」は、トラックが常に記憶しています。

- オートポルタメントが停止している間も、記憶は更新されます。
- 休符をはさんでも忘れません。
- トラック開始時の値は、`o0c`（音程番号 0）です。

タイ・スラー（`&`）で繋がれた音符も、実際に鳴っている音符として記憶が更新されます。  
ただし、滑りを組み直すのはノートオンのときだけで、ノートオンを伴わない継続部分では組み直しません。  
例外として、`sys22rr` 型だけは、スラーで音程が変わるときにも滑りを組み直します。（後述）

### 変化の更新周期：

音程の変化は、ＬＦＯ解像度設定（`@lor`コマンド、または `#MB:CONFIG` の `lfo_resol`）で決まる周期ごとに行われます。

### テンポ変更との関係：

変化に要する時間は、テンポ変更（`t`コマンド）に追従しません。

- テンポを遅くした場合：譜面上は短い区間で到達し、そのまま維持されます。
- テンポを速くした場合：音符が終わる時点で、強制的に到達音程になります。

### 到達後：

目標の音程に到達した後は、その音程で固定されます。行き過ぎることはありません。

### ポルタメント（`_`）との関係：

`_` によるポルタメントと同時に掛けることができます。両方が掛かっている音符では、それぞれの音程変位が合計されます。

[（ポルタメントとは）](2_18.md)

## 【`sys2lv` 型について】

`sys2lv` は機種互換の型で、時間で指定する４つの型とは仕様が異なります。

### 引数[1] の意味：

移植元ＲＯＭのコマンド引数の値を、そのまま記述します。  
設定範囲は 0 < 引数[1] ≦ 255 です。

- 値が 小さいほど速く、大きいほど遅くなります。
- この型では小数点以下は切り捨てられます。`@ap60.9` は `@ap60` と同じ動作になります。
- 256 以上を指定すると、エラーになります。

### 到達までの時間：

`sys2lv` は経過時間ではなく、更新のたびに残りの音程差を縮める漸化式で動きます。このため、到達までの時間は「更新回数 × 更新周期」で決まります。

引数[1] を等間隔に振っても、到達までの段数は等間隔になりません。  
音程差 12半音 の場合の例は次の通りです。

|引数[1]|変化の段数|
|:-:|:-:|
|1|5 段|
|40|6 段|
|60|7 段|
|100|9 段|
|120|11 段|
|254|792 段|
|255|到達しません|

このうち最初の１段はノートオンの時点で消費されるため、ノートオンから到達までに掛かる時間は、次のようになります。

```
到達までの時間 ＝ (変化の段数 − 1) × 更新周期
```

移植元と同じ速さにするには、更新周期が 8.15625msec になるように、`lfo_resol` とテンポを設定します。更新周期を変えると、到達までの時間は正比例で変わります。

※引数[1] が 255 のときは、最後の 1/256 半音を詰める段階で変化量が０になるため、目標音程に到達しません。これは移植元の整数演算の動作をそのまま再現したものです。

### 開始音程が鳴らないこと：

`sys2lv` では、ノートオンの時点ですでに漸化式が１回進んだ状態になっています。  
このため、開始音程（直前の音符の高さ）は一度も鳴りません。

時間で指定する４つの型では、開始音程から変化が始まります。この違いは、移植元のサウンドドライバの動作を再現するための、意図的なものです。

---

## 【`sys22rr` 型について】

`sys22rr` も機種互換の型で、`sys2lv` と同じく、更新のたびに残りの音程差を縮める漸化式で動きます。  
`sys2lv` との違いは、「下降のほうが速いこと」と「スラーでも滑ること」の２つです。

### `sys2lv` と同じところ：

- 引数[1] の書き方と範囲（0 < 引数[1] ≦ 255。小数点以下は切り捨て。256 以上はエラー）
- 値が小さいほど速いこと。引数[1] ＝ 256 − 移植元の速度 です
- `@ap%` が使えないこと
- ノートオンの時点ですでに１回進んでいて、開始音程が鳴らないこと
- 到達までの時間が「更新回数 × 更新周期」で決まること。移植元と同じ速さにするには、更新周期を移植元の 1 tick に合わせます

### 下降のほうが速いこと：

移植元は、残りの音程差を符号つきのまま計算するため、下降のほうが速く着きます。上昇は `sys2lv` とまったく同じです。

音程差 12半音 の場合の、変化の段数（ノートオンの１段を含む）は次の通りです。

|引数[1]|上昇（`sys2lv` と同じ）|下降|
|:-:|:-:|:-:|
|1|5 段|4 段|
|40|6 段|4 段|
|60|7 段|5 段|
|100|9 段|7 段|
|120|11 段|8 段|
|226|52 段|37 段|
|254|792 段|557 段|
|255|到達しません|1034 段|

差は着地の直前に集まります。最後の１半音を詰める速さが、上昇では 1 更新あたり 速度/2、下降では 速度 になります。

1 回の更新は、次の式で行われます（音程は 1/256 半音単位、Δ ＝ 目標 − 今の音程）。

```
Δ が 0 なら何もしない
h    ＝ floor(Δ / 256)
m    ＝ (Δ ≧ 0) ? h + 1 : h − 1
歩幅 ＝ floor(m × 速度 / 2)        （−∞ 方向への切り捨て）
今の音程 ＝ 今の音程 + 歩幅。目標に着いたか、越えたら目標の音程にする
```

※引数[1] が 255 のとき、上昇は `sys2lv` と同じく最後の 1/256 半音を詰められず到達しませんが、下降は歩幅が −1 になるので到達します。

### スラーでも滑ること：

`sys22rr` では、スラー（`&` で繋いだ、ノートオンを伴わない音）で音程が変わるときにも、滑りを組み直します。移植元のサウンドドライバが、ノートオンしない音でも目標の音程へ滑るためです。

```mml
@ap106 c4&d4&e4      ← c から d、d から e へ、それぞれ滑る
```

- 始点は、そのとき鳴っている高さです。前の音がまだ滑っている途中なら、その途中の高さから滑ります。引数[2]（始点の音程番号）は使いません。
- 速さは、スラーの時点で有効な `@ap` の引数[1] です。オートポルタメントが停止している（引数[1] が ０以下）ときは、組み直しません。
- ノートオンと同じく、スラーの時点ですでに１回進んだ高さが鳴ります。
- 以後の更新の周期は、ノートオンから数えたままです。スラーが更新と更新の間に来たときは、その場で１回進んだ後、次の更新から続けます。
- エンベロープや LFO はノートオンし直しません。変わるのは音程の滑りだけです。

他の５つの型（`sys2lv` を含む）では、スラーの音程は今までどおり瞬時に変わります。

## 【表示】

### KeyDispへの表示：

`@ap` の設定内容は、KeyDispの表示に反映されます。  
`@ap%` で指定した場合は `@ap%8` のように、`%` 付きで表示されます。引数[2] は表示されません。

### `!c` への表示：

ＭＭＬステータス表示（`!c`）では、`@ap` と `@ap%` が、それぞれ別の枠で表示されます。

|記述|`!c` の表示|
|:-|:-|
|一度も記述していない|`@apz @ap%0`|
|`@apz` / `@ap0` / `@ap%0`|`@apz @ap%0`|
|`@ap%8` だけを記述|`@apz @ap%8,-1`|
|`@ap80,60` だけを記述|`@ap80,60 @ap%0`|
|`@ap10` と `@ap%20` を記述|`@ap10,-1 @ap%20,-1`|

※`@apz` は `@ap` 側と `@ap%` 側の両方を停止させるため、`!c[1],[cmp]` で設定回数を絞った場合、両方の枠が対象になります。

[（ＭＭＬステータス表示とは）](../ch05/5_11.md)

## 【備考】数値省略記号「`#`」との関係

数値省略記号「`#`」で直前の指定値を参照する場合、`@ap` と `@ap%` は別々の履歴を持ちます。  
`@ap` に書いた `#` は `@ap` の履歴を、`@ap%` に書いた `#` は `@ap%` の履歴を参照します。

引数[2] も、引数[1] とは別の履歴を持ちます。

[（数値「`#`」の記述とは）](../ch01/1_5_1.md)
