# 6.38 `#MB:EFFECTOR_BUS`：エフェクターのバス定義
# 6.39 `@bf[1]`／`#MB:BUS_FEED`：バスへの送り方

[← 目次](../index.md)

## 【記述例】

```mml
#MB:EFFECTOR_BUS 1 { type=delay_infinite, msec=300, dB=-8, }
#MB:BUS_FEED @bf=1 { route_bus=0, route_lv=0dB, send_bus=1, send_lv=0dB, }
t120 @@"pls" o4 l8 q6,8 @bf1 cegefdgg cegefdg&g;
```

上記のように書くと、

- `#MB:EFFECTOR_BUS` によって、バス１番にディレイを置きます。
- `#MB:BUS_FEED` によって、定義番号１番の送り方を「原音はそのまま全体（バス０）へ、同じ音をバス１番のディレイへも」と定義します。
- `@bf1`によって、このトラックの音を、定義番号１番の送り方で送ります。

といった定義と適用を記述できます。

## 【解説】

### エフェクターのバスとは

エフェクターのバスは、トラックの音を集めてエフェクト（フィルタやディレイ）を掛ける、曲全体で共有する通り道です。  
トラックごとにエフェクトを掛けるのではなく、いくつものトラックの音を 1 つのバスに集めて、まとめて掛けます。  
同じディレイを多くのトラックに掛けるときも、ディレイの計算はバス 1 本ぶんで済みます。

バスは次の 10 本で、つながり方は決まっています（変えられません）。

```
                  3 段目   2 段目      1 段目     バス 0
   トラック ─@bf→  [41] ──→ [21] ──────→ [1] ──┐
   トラック ─@bf→  [42] ──→ [22] ──────→ [2] ──┼──→ [0] → 出力
   トラック ─@bf→  [43] ──→ [23] ──────→ [3] ──┘     ↑
   トラック ─@bf→ (21〜23・1〜3 へ直接も送れる)      トラックの原音 (@bf で 0 へ)
```

- バス０は、全トラックの音を足し終えた、曲全体の音そのものです。
- ３段目のバス 40+k（41〜43）の出口は、対になる２段目のバス 20+k（21〜23）へ入ります。
- ２段目のバス 20+k（21〜23）の出口は、対になる１段目のバス k（1〜3）へ入ります。
- １段目のバス 1〜3 の出口は、バス０へ入ります。
- ２段目・１段目のバスには、1 つ上の段の対のバスの出口と、トラックから直接送られた音の両方が入ります。
- 1 本のバスに置けるエフェクトは 1 つです。フィルタを掛けてからディレイを掛けるときは、２段目にフィルタ、１段目にディレイを置きます。
  フィルタを 2 つ重ねてからディレイを掛けるときは、３段目・２段目・１段目に順に置きます。
- バスの番号は、段ごとに帯を分けています（１段目 1〜20、２段目 21〜40、３段目 41〜60）。今使えるのは上の 10 本です。
- バスの中身は、曲の途中では変わりません。

### 1 回の処理の順

1. 全トラックを鳴らし、各トラックはパンを振った後の音を `@bf` の送り方でバスへ送ります。
2. ３段目のバス 41〜43 を処理し、出口を対の２段目へ足します。
3. ２段目のバス 21〜23 を処理し、出口を対の１段目へ足します。
4. １段目のバス 1〜3 を処理し、出口をバス０へ足します。
5. バス０にエフェクトがあれば、曲全体の音に掛けます。

各バスの出口は、次の式で決まります（左右それぞれ）。

```
出口 = エフェクトを掛けた音 × out_wet_lv ＋ 入口の音 × out_dry_lv
```

同じ処理の中で順に流れるので、バスを通ることによる遅れはありません。  
バスの処理は曲の一部なので、再生でも書き出しでも同じように掛かります。  
曲の終わりの後の休符の間も、ディレイの響きは流れ続けます。

## 6.38 エフェクターのバス定義（`#MB:EFFECTOR_BUS`）：

バスの状態と、置くエフェクトを定義します。
定義方法の概要は次の通りです。

- 行頭からの記述で、キーワード「`#MB:EFFECTOR_BUS`」を書く。
- 続けて、スペースを置き、バスの番号を書く（「@…=」のようなラベルは付けません）。
- 続けて、スペースを置き、中括弧「{}」で括られた設定データを書く。

```
#MB:EFFECTOR_BUS バスの番号 { type=種類, 項目=値, … }
```

### バスの番号：

0・1〜3・21〜23・41〜43 のどれかです。それ以外の番号はエラーになります。  
同じ番号を 2 回書いたときは、後に書いたほうが使われます。  
定義を書かなかったバスは、無効（`type=null`）です。ただしバス０は、書かなければ `type=through`（そのまま通す）です。

### 設定データ：

`type=` を必ず先頭に書きます。

|項目名|内容|設定範囲|初期値|
|:-:|:-|:-|:-|
|`type`|バスの状態、またはエフェクトの種類|`null`・`through`・下の種類|－|
|`out_wet_lv`|エフェクトを掛けた音を出口に足す量（左右共通）|量の値|1（0dB）|
|`out_dry_lv`|入口の音を、エフェクトを掛けずに出口に足す量|量の値|0（足さない）|

|`type`|書ける項目|内容|
|:-:|:-|:-|
|`null`|なし|無効。計算もしません。バス０には書けません。|
|`through`|`out_wet_lv`|入口の音をそのまま出します（`out_wet_lv` が音量のつまみになります）。|
|`filter_…`|全部|biquad フィルタ（下記）|
|`delay_…`|全部|ディレイ（下記）|
|`reverb_spu`|全部|特定の音源チップ型のリバーブ（下記）|

#### 量の値：

`out_wet_lv`・`out_dry_lv`・`#MB:BUS_FEED` の `route_lv`・`send_lv` は、量の値です。

- 後ろに「`dB`」を付けると、デシベルで書けます（例：`-3dB`）。範囲の制限はありません。
- 「`dB`」を付けなければ、倍率です。設定範囲は -1.0 〜 1.0 です。負の値は位相を反転します。
- 0 は「足さない」です。

---

### `type=filter_…` のとき（biquad フィルタ）

静的フィルタ定義（`#MB:FILTER_S`、[6.45](6_44n45.md)）の種類の名前の頭に「`filter_`」を付けたものです。  
種類ごとの項目と設定範囲は、`#MB:FILTER_S` と同じです。左右に同じ係数のフィルタを掛けます。

|`type`|項目|
|:-|:-|
|`filter_bq_lpf`|`freq`, `q`|
|`filter_bq_lpf2p`|`freq_lpf2p`|
|`filter_bq_hpf`|`freq`, `q`|
|`filter_bq_bpf`|`freq`, `bw`|
|`filter_bq_notch`|`freq`, `bw`|
|`filter_bq_apf`|`freq`, `q`|
|`filter_bq_lsf`|`freq`, `q`, `dB`|
|`filter_bq_hsf`|`freq`, `q`, `dB`|
|`filter_bq_peaking`|`freq`, `bw`, `dB`|
|`filter_bq_lsflpf`|`freq_lsf`, `q_lsf`, `dB_lsf`, `freq_lpf`, `q_lpf`|
|`filter_bq_lsflpf2p`|`freq_lsf`, `q_lsf`, `dB_lsf`, `freq_lpf2p`|
|`filter_bq_eq2band`|`freq_l`, `q_l`, `dB_l`, `freq_h`, `q_h`, `dB_h`|
|`filter_bq_eq3band`|`freq_l`, `q_l`, `dB_l`, `freq_m`, `bw_m`, `dB_m`, `freq_h`, `q_h`, `dB_h`|

`#MB:FILTER_S` の `type=off` はありません（`through`・`null` を使います）。

#### 【記述例】

```
#MB:EFFECTOR_BUS 0 { type=filter_bq_hpf, freq=40, q=1/(2^0.5), }
```

曲全体（バス０）に、40Hz のハイパスフィルタを掛けます。

### `type=delay_…` のとき（ディレイ）

ディレイの出口には、遅れた音（エコー）だけが出ます。元の音は出ません。  
元の音も出したいときは、`out_dry_lv` を書きます。ふつうは、元の音をトラックからバス０へ直接送り（`route_bus=0`）、エコーだけをディレイのバスから足します。

左右に同じ設定の遅延線を 1 本ずつ持ちます。

#### `type=delay_infinite`（無限回数）

```
#MB:EFFECTOR_BUS 1 {
   type=delay_infinite, msec=300, dB=-8,
}
```

フィードバックによる無限回数ディレイ加算を行います。上の例は、遅延 300ms・減衰 -8dB です。

|項目名|内容|
|:-:|:-|
|msec|１次遅延の時間（ミリ秒）。設定範囲は 0.05 〜 5000.0|
|dB|１次遅延の振幅を、元に比べて何デシベルにするか。設定範囲は -0.2 〜 -96.0|

#### `type=delay_infinite_bqbpf` と `type=delay_infinite_bqbpf_r`

```
#MB:EFFECTOR_BUS 1 {
   type=delay_infinite_bqbpf, msec=300, dB=-8,
   freq=1000, bw=1.0,
}
#MB:EFFECTOR_BUS 2 {
   type=delay_infinite_bqbpf_r, msec=300, dB=-8,
   freq=1000, bw=1.0,
}
```

フィードバックによる無限回数ディレイ加算を、バンドパスフィルタを伴って行います。  
「`_r`」が付かない方は、元の音をディレイに送るときにだけバンドパスが掛かるので、バンドパスの対象は最初のディレイだけになります。  
「`_r`」が付く方は、フィードバックで加算する音にバンドパスが掛かるので、バンドパスが繰り返し掛かります。

|項目名|内容|
|:-:|:-|
|msec|１次遅延の時間（ミリ秒）。設定範囲は 0.05 〜 5000.0|
|dB|１次遅延の振幅比（dB）。設定範囲は -0.2 〜 -96.0|
|freq|バンドパスフィルタのカットオフ周波数（Hz）。設定範囲は 40.0 〜 384000.0|
|bw|バンドパスフィルタの帯域幅。0.0 より大きい値|

帯域幅（`bw`）は、例えば次のような特性になります。

- `bw`=1のとき、カットオフ周波数から±１オクターブが-3dBとなります。
- `bw`=2のとき、カットオフ周波数から±２オクターブが-3dBとなります。

`bw`の数値が小さくなるほど、カットオフ周波数からの通過幅が狭くなります。

#### `type=delay_finite1` 〜 `type=delay_finite6`（有限１〜６回）

```
#MB:EFFECTOR_BUS 1 {
   type=delay_finite1, msec1=300, dB1=-6,
}
#MB:EFFECTOR_BUS 2 {
   type=delay_finite3,
   msec1=200, dB1=-6,
   msec2=400, dB2=-9,
   msec3=600, dB3=-12,
}
```

次数１〜次数６の定義に従って、遅延加算を行います。`delay_finite`N のときは、`msec1`・`dB1` 〜 `msec`N・`dB`N を書きます。

|項目名|内容|
|:-:|:-|
|msec1 〜 msec6|１次〜６次遅延の時間（ミリ秒）。設定範囲は 0.05 〜 5000.0|
|dB1 〜 dB6|１次〜６次遅延の振幅比（dB）。設定範囲は -0.2 〜 -96.0|

#### `type=delay_finite1_bqbpf` 〜 `type=delay_finite6_bqbpf`（BPF&有限１〜６回）

```
#MB:EFFECTOR_BUS 1 {
   type=delay_finite2_bqbpf,
   msec1=200, dB1=-6,
   msec2=400, dB2=-9,
   freq=1000, bw=1.0,
}
```

`delay_finite1` 〜 `delay_finite6` に、バンドパスフィルタを伴わせたものです。  
項目は、`delay_finite`N の項目に `freq`・`bw`（`delay_infinite_bqbpf` と同じ）を加えたものです。

### `type=reverb_spu` のとき（特定の音源チップ型のリバーブ）

特定の音源チップが持つリバーブと同じ形の式と、同じ 10 種類のプリセットで響きを作ります。  
元のチップは 22,050Hz・16 ビットの整数で計算します。V3MML は同じ式を、倍精度の浮動小数点数で、384,000Hz のまま計算します。  
値を 16 ビットに収めない（飽和しない）ので、元のチップより高い音域まで響き、大きな音でも歪みません。

#### 【記述例】

```
#MB:EFFECTOR_BUS 1 { type=reverb_spu, preset=studio_large, evol_l=0.165, evol_r=0.165, }
#MB:BUS_FEED @bf=1 { route_bus=0, route_lv=0dB, send_bus=1, send_lv=0dB, }
t120 @@"pls" o4 l8 q6,8 @bf1 cegefdgg cegefdg&g;
```

バス１番に `studio_large` のリバーブを置き、響きの量を左右とも 0.165 倍にします。  
`@bf1` のトラックの原音はバス０へ、同じ音がバス１番のリバーブへも送られます。  
リバーブの出口には、響きだけが出ます（元の音は出ません）。ディレイと同じく、ふつうは原音をトラックからバス０へ直接送ります。

元のチップの響きの量（出力の音量）を写すときは、その値を `evol_l`・`evol_r` に書き、`out_wet_lv` は省きます（1 のまま）。

#### 項目：

|項目名|内容|設定範囲|初期値|
|:-:|:-|:-|:-|
|`preset`|プリセット（下の表）|`off`・`room`・`studio_small`・`studio_medium`・`studio_large`・`hall`・`space_echo`・`chaos_echo`・`delay`・`half_echo`|必須（省くとエラー）|
|`lpf_cutoff`|響きの出口に掛けるローパスのカットオフ周波数（Hz）|1 〜 191992。-1 は掛けない|-1（掛けない）|
|`work`|作業領域の大きさ（バイト）|1 〜 524288 の整数|プリセットの値|
|`spu_delay`|`chaos_echo`・`delay` の遅れ|0 〜 127 の整数|127|
|`spu_feedback`|`chaos_echo` の帰還の量|0 〜 127 の整数|127|
|`evol_l`|響きの出力の量（左）|量の値|1.0|
|`evol_r`|響きの出力の量（右）|量の値|1.0|
|`in_l`|入力の倍率（左）|量の値|プリセットの値（-1.0）|
|`in_r`|入力の倍率（右）|量の値|プリセットの値（-1.0）|
|30 個の設定|元のチップの設定の値（下記）|0 〜 0xFFFF の整数|プリセットの値|

- `evol_l`・`evol_r`・`in_l`・`in_r` は量の値です（6.38 の「量の値」と同じ。負の倍率は位相を反転します）。
- プリセットの入力の倍率は、左右とも -1.0（位相を反転して入れる）です。
- `spu_delay` は `preset=chaos_echo`・`delay` のときだけ、`spu_feedback` は `preset=chaos_echo` のときだけ書けます。ほかのプリセットで書くとエラーです。
- `out_wet_lv`・`out_dry_lv` も書けます。出口は「響き × `out_wet_lv` ＋ 入口 × `out_dry_lv`」です。

#### プリセット：

|`preset`|作業領域（バイト）|作業領域の長さ|響きの始まり（左に入れたとき）|残響時間の目安|
|:-|-:|-:|:-|:-|
|`off`|16|－|響きは出ません|－|
|`room`|9,920|0.22 秒|左 41.7ms（右へは回り込みません）|約 0.74 秒|
|`studio_small`|8,000|0.18 秒|左 8.2ms・右 53.3ms|約 0.86 秒|
|`studio_medium`|18,496|0.42 秒|左 40.1ms・右 134.6ms|約 0.86 秒|
|`studio_large`|28,640|0.65 秒|左 43.0ms・右 193.0ms|約 2.0 秒|
|`hall`|44,512|1.01 秒|左 45.0ms・右 278.3ms|約 2.1 秒|
|`space_echo`|63,168|1.43 秒|左 81.6ms・右 313.5ms|約 4.0 秒|
|`chaos_echo`|98,368|2.23 秒|左 742ms（`spu_delay=127`）|ほぼ終わらないエコー|
|`delay`|98,368|2.23 秒|左 742ms（`spu_delay=127`）|1 回だけのエコー|
|`half_echo`|15,360|0.35 秒|左 25.4ms・右 29.6ms|約 1.3 秒|

- 作業領域の長さは、元のチップの周波数（22,050Hz）で数えた、作業領域に入る時間です（作業領域の大きさ ÷ 2 ÷ 22050）。
- 響きの始まりと残響時間は、左だけに短い音を入れて測った値です。残響時間は、響きのエネルギーが -5dB から -25dB へ減る傾きから求めました。

#### 30 個の設定：

元のチップのリバーブの設定のうち、入力の倍率（`in_l`・`in_r` で書く）を除いた 30 個を、名前でじかに書けます。  
値は元のチップの生の値（16 ビット。「0x」を付けると 16 進）です。大文字・小文字は名前のとおりに書きます。

|種類|名前|値の意味|
|:-|:-|:-|
|倍率|`vIIR`・`vCOMB1`〜`vCOMB4`・`vWALL`・`vAPF1`・`vAPF2`|符号つき 16 ビットの値 ÷ 32768（0x8000 が -1.0、0x7FFF がほぼ 1.0）|
|位置|`dAPF1`・`dAPF2`・`mLSAME`・`mRSAME`・`mLCOMB1`・`mRCOMB1`・`mLCOMB2`・`mRCOMB2`・`dLSAME`・`dRSAME`・`mLDIFF`・`mRDIFF`・`mLCOMB3`・`mRCOMB3`・`mLCOMB4`・`mRCOMB4`・`dLDIFF`・`dRDIFF`・`mLAPF1`・`mRAPF1`・`mLAPF2`・`mRAPF2`|作業領域の中の位置（8 バイト単位。符号なし）|

位置と倍率は、384,000Hz で計算するために、次のように直して使います。

- 位置は、元のチップの周波数で数えた位置を 384000 ÷ 22050 倍し、整数に丸めます。
- `vIIR` は、1 秒あたりの減り方が元のチップと同じになるように直します。

#### 値の決まる順：

1. プリセットの値（30 個の設定・`in_l`・`in_r`・`work`）
2. `spu_delay`・`spu_feedback` による作り直し（`chaos_echo`・`delay` のとき）
3. 書いた項目による上書き（30 個の設定・`in_l`・`in_r`・`work`）

`spu_delay` は遅れに関わる 6 つの位置を、`spu_feedback` は `vWALL` を、特定ドライバと同じ整数の計算で作り直します。どちらも 127 のときはプリセットの値のままです。  
上書きは作り直しの後なので、作り直した位置も、30 個の設定で上書きできます。

#### 作業領域：

作業領域は 1 本で、左右の響きが同じ領域を使います。  
位置は作業領域の長さで折り返します。作業領域の外を指す位置もエラーにはならず、折り返した位置を読み書きします（プリセット自体が折り返しを使っています）。  
`work` を書くと、作業領域の大きさを変えられます。小さくすると、折り返しで響きの形が変わります。

作業領域は、384,000Hz で数えた数だけ倍精度の値を持ちます。大きさの目安は `studio_large` で約 2MB、`chaos_echo`・`delay` で約 7MB です。再生用と書き出し用に 1 つずつ持ちます。

#### `lpf_cutoff`（響きの出口のローパス）：

響きの出口に、biquad のローパスフィルタ（-12dB/oct、Q = 1/√2）を 1 段掛けます。響きの高い音域を削り、元のチップの響きに近い暗さにしたいときに使います（元のチップの響きには、約 11kHz より上がありません）。

```
#MB:EFFECTOR_BUS 1 { type=reverb_spu, preset=studio_large, lpf_cutoff=11025, }
```

設定範囲の上限 191992Hz は、384,000Hz の半分より少し下です。半分ちょうどにすると、フィルタの計算が安定の境目に乗り、丸めの誤差が大きくなり続けるためです。

#### 表示：

ＭＭＬステータス表示（`!s`）のバスの状態には、書いたとおりの項目が表示されます（例：`1{ type=reverb_spu, preset=studio_large, evol_l=0.165, evol_r=0.165 }`）。

## 6.39 バスへの送り方（`#MB:BUS_FEED`）とその適用（`@bf[1]`）：

### 送り方の定義（`#MB:BUS_FEED`）：

トラックの音を、どのバスへ、どれだけ送るかを定義します。

- 行頭からの記述で、キーワード「`#MB:BUS_FEED`」を書く。
- 続けて、スペースを置き、「@bf=定義番号」を書く。
- 続けて、スペースを置き、中括弧「{}」で括られた設定データを書く。

```
#MB:BUS_FEED @bf=定義番号 {
   route_bus=[], route_lv=[],
   send_bus=[],  send_lv=[],
}
```

|項目名|内容|
|:-:|:-|
|`route_bus`|１つ目の宛先のバス（0・1〜3・21〜23・41〜43）|
|`route_lv`|１つ目の宛先へ送る量（量の値）|
|`send_bus`|２つ目の宛先のバス（0・1〜3・21〜23・41〜43）|
|`send_lv`|２つ目の宛先へ送る量（量の値）|

- 4 つの項目は、すべて必ず書きます。1 つでも欠けるとエラーになります。
- トラックの音は、常に 2 つの宛先へ、それぞれの量を掛けて送られます。
- 量が 0 の宛先には送りません（計算もしません）。このとき宛先は使われませんが、`0` と書くことにします。
- 慣例として、`route` は原音の行き先（ふつうはバス０）、`send` はエフェクトのバスへの送りに使いますが、決まりではありません。`route_bus` と `send_bus` が同じでもかまいません（同じバスに 2 回足します）。
- 送るのは、パンを振った後のステレオの音です（エンベロープ・フェード・振幅反転 `px` が掛かった後の音）。

定義番号の設定範囲は 0 〜 999 です。`#MB:BUS_FEED` の定義は 512 個までです。  
同じ定義番号を 2 回書いたときは、後に書いたほうが使われます。

### 送り方コマンド（`@bf[1]`）：

送り方の定義（`#MB:BUS_FEED`）の定義番号を整数で指定します。  
未定義の番号を指定するとエラーになります（0 番も同じです。`#MB:BUS_FEED @bf=0` と定義すれば、0 番も使えます）。

トラックの先頭は `@bfz`（[6.40](6_40.md)）と同じ状態で、音はそのままバス０へ送られます。何も書かないトラックの音は、これまでどおり曲全体の音に足されるだけです。

- 単音のトラックでは、すぐに効きます。
- ポリモード（`@pl`）では、`v` や `@p` と同じく、次のノートオンから、そのボイスに効きます。
- キーイベント（`@kc`・`@kt`・`@kl`）の宛先 `target=@bf` で、鍵盤などごとに送り方を変えられます。

### ★ディレイの響きは、送った時点の音のまま鳴ります

バスのディレイには、送った時点の音が溜まります。そのため、音符の後に残る響きは、後で `@p`（パン）や `px`（振幅反転）や `@bf` を変えても、送ったときのパン・反転のまま鳴ります。  
`@bfz` に切り替えても、すでにバスに送った音の響きは止まりません。

### 表示：

- KeyDisp には、今の送り方の番号が `@bf1` のように表示されます。`@bfz` の状態では表示されません。定義した `@bf0` は `@bf0` と表示されます。
- ＭＭＬステータス表示（`!s`）には、送り方の番号と定義の中身（`@bf1{ route_bus=0, … }`）と、バスの状態（`bus 0{ type=through } 1{ type=delay_infinite, … }`。`#MB:EFFECTOR_BUS` を書いた曲だけ）が表示されます。

---

## 【エラー】

次のときはエラーになります。

- 有効でないバスの番号（4〜20、24〜40、44 以上など）を、`#MB:EFFECTOR_BUS` の番号や、`route_bus`・`send_bus` に書いた。
- `#MB:EFFECTOR_BUS` の先頭に `type=` が無い、未定義の種類、`type=null` にほかの項目、`type=through` に `out_dry_lv`、種類ごとの項目の誤り（`#MB:FILTER_S` と同じ確かめ）。
- `type=reverb_spu` で、`preset` が無い、未定義のプリセット、項目が範囲の外（`lpf_cutoff`・`work`・`spu_delay`・`spu_feedback`・30 個の設定・量の値）、知らない項目名、同じ項目を 2 回書いた、`spu_delay` を `chaos_echo`・`delay` 以外で書いた、`spu_feedback` を `chaos_echo` 以外で書いた。
- バス０に `type=null` を書いた。
- ２段目のバス 20+k を定義したのに、対の１段目のバス k を定義していない。
- ３段目のバス 40+k を定義したのに、通り道の２段目のバス 20+k と１段目のバス k の両方は定義していない。
- `#MB:BUS_FEED` の宛先が定義していない（`null` の）バスで、その側の量が 0 でない。
- `#MB:BUS_FEED` の 4 つの項目のどれかが無い。
- `@bf` に未定義の番号を書いた、または番号を省略した。

## 【例】

### 例 1：送った音だけにローパスを掛けてからディレイ（2 段）

```
#MB:EFFECTOR_BUS 21 { type=filter_bq_lpf, freq=3000, q=1/(2^0.5), }
#MB:EFFECTOR_BUS 1  { type=delay_infinite, msec=300, dB=-8, }
#MB:BUS_FEED @bf=1 { route_bus=0, route_lv=0dB, send_bus=21, send_lv=0dB, }
```

`@bf1` のトラックの原音はバス０へ、同じ音がバス 21（ローパス）→ バス 1（ディレイ）→ バス０と流れます。

### 例 2：トラックの音そのものにローパスを掛け、その音にディレイも（2 段 ＋ `out_dry_lv`）

```
#MB:EFFECTOR_BUS 22 { type=filter_bq_lpf, freq=3000, q=1/(2^0.5), }
#MB:EFFECTOR_BUS 2  { type=delay_infinite, msec=300, dB=-8, out_dry_lv=0dB, }
#MB:BUS_FEED @bf=2 { route_bus=22, route_lv=0dB, send_bus=0, send_lv=0, }
```

`@bf2` のトラックの音は、バス 22（ローパス）→ バス 2 → バス０と流れます。バス 2 の出口は「ローパスを掛けた音 ＋ そのエコー」で、原音は直接バス０へは行きません。

### 例 3：いくつかのトラックをまとめて EQ（サブミックス）

```
#MB:EFFECTOR_BUS 3 { type=filter_bq_eq2band, freq_l=100, q_l=1/(2^0.5), dB_l=3,
                     freq_h=8000, q_h=1/(2^0.5), dB_h=-4, out_wet_lv=-3dB, }
#MB:BUS_FEED @bf=3 { route_bus=3, route_lv=0dB, send_bus=0, send_lv=0, }
```

キックとスネアのトラックに `@bf3` を書き、ベースのトラックには何も書きません。キックとスネアだけがバス 3 の EQ を通ります。

### 例 4：曲全体に掛ける（バス０）

```
#MB:EFFECTOR_BUS 0 { type=filter_bq_hpf, freq=40, q=1/(2^0.5), }
```

`@bf` を書かなくても、全トラックの音に掛かります。

### 例 5：キーイベントで、鍵盤ごとに送る・送らない

```
#MB:EFFECTOR_BUS 1 { type=delay_infinite, msec=300, dB=-8, }
#MB:BUS_FEED @bf=0 { route_bus=0, route_lv=0dB, send_bus=0, send_lv=0, }      // 送らない
#MB:BUS_FEED @bf=1 { route_bus=0, route_lv=0dB, send_bus=1, send_lv=0dB, }    // 送る
#MB:KEYEVENT_CODE @kc=1 {
   target=@bf |
   [R:60:0,] [R:60:1,]
}
```

`@kc1` のトラックでは、音程番号 0 〜 59 の音は送らず、60 〜 119 の音だけをディレイへ送ります。

### 例 6：以前の `@dl` からの書き直し

以前の `@dl`・`@dlz`・`#MB:DELAY`（トラックごとのディレイ）は廃止しました。書くと、廃止した旨のエラーになります。次のように書き直します。

```
旧:  #MB:DELAY @dl=1 { type=infinite, msec=300, dB=-8, }      トラック: @dl1
新:  #MB:EFFECTOR_BUS 1 { type=delay_infinite, msec=300, dB=-8, }
     #MB:BUS_FEED @bf=1 { route_bus=0, route_lv=0dB, send_bus=1, send_lv=0dB, }
     トラック: @bf1
```

`@dlz` は `@bfz` に書き直します。  
ディレイの種類の名前は、頭に「`delay_`」を付けます。項目と設定範囲は以前と同じです。  
以前のディレイと違い、音符の後に残る響きは、送った時点のパン・振幅反転のまま鳴ります。また `@bfz` に切り替えても、すでに送った音の響きは止まりません。
