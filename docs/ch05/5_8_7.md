# 5.8.7 機能名：`lfo_resol`：ＬＦＯ解像度設定

[← 目次](../index.md)

## 【記述例】

```mml
#MB:CONFIG {
   lfo_resol: unit=sec: rate=1/300,
}
```

## 【解説】

ＬＦＯ時間軸の解像度（ＬＦＯ変位計算の最小時間単位）を設定します。  
この設定は全トラックへの初期値となります。  
この設定が有効になる対象は次の通りです。

- ピッチＬＦＯ
- yコマンドＬＦＯ
- フィルタＬＦＯ

当設定を使用しなかった場合の初期設定は次の通りです。

```mml
#MB:CONFIG {
   lfo_resol: unit=sec: rate=1/600,
}
```

### 項目名(1)：`unit`

定義値には、時間単位を文字列で指定します。

|設定文字列|ＬＦＯ解像度単位 設定内容|
|:-:|:-:|
|`sec`|時間単位は「１秒」|
|`tick`|時間単位は「１tickカウント」|
|`clock`|時間単位は「ＬＦＯクロック（`lfo_clock`）の１単位」|

### 項目名(2)：`rate`

定義値には、時間単位に対する倍率を数値（計算式）で指定します。  
時間単位が「`sec`」だった場合、`rate`の有効範囲は、1/3000 〜 1 になります。  
時間単位が「`tick`」または「`clock`」だった場合、`rate`の有効範囲は、０より大きい値です。

#### 【備考１】

ＬＦＯ解像度は、ポルタメント機能による周波数変更の最小時間単位にもなっています。

#### 【備考２】

時間単位が「１tickカウント」の場合、テンポにより時間単位が変動します。

#### 【備考３】

音量とパンポットのＬＦＯ（@la / @lb）は、常に1サンプル単位で動作するので、本機能の対象外になります。

#### 【備考４】時間単位が「`clock`」の場合

時間単位が「`clock`」の場合、区切り（ＬＦＯの値を書き換える間隔）の長さは「`rate` × ＬＦＯクロック（`lfo_clock`）の１単位」になります。区切りはＬＦＯクロックに連動し、区切りの位置は音符の頭から数えた絶対位置で決まるので、長い音符でも区切りのずれがたまりません（常に１サンプル以内）。

`rate` の読み方の例：

```mml
#MB:CONFIG {
   lfo_clock: unit=tick: rate=1,
   lfo_resol: unit=clock: rate=1/4,     /* ＬＦＯクロックの１単位（１tick）を４回に分けて更新する */
}
```

```mml
#MB:CONFIG {
   lfo_clock: unit=tick: rate=1,
   lfo_resol: unit=clock: rate=4,       /* ＬＦＯクロックの４単位（４tick）ごとに１回更新する（階段状の効果） */
}
```

どちらの書き方も「区切り ＝ `rate` × ＬＦＯクロックの１単位」という同じ決まりで動きます。

- テーブルＬＦＯの `width_mode=step` は「１要素に区切りいくつ」なので、`lfo_resol: unit=clock: rate=1` と組み合わせると「１要素に何単位」になります。
- テンポが変わると、区切りの位置をＬＦＯクロックの単位で保ったまま、残りを新しいテンポの長さに直して続けます（ＬＦＯクロックが `tick` のとき）。
- 区切りは、ノートオン、`@lp` などのＬＦＯ設定・`@lpr` などのＬＦＯ再スタート、`@loc` / `@lor` の位置から数え直します。
- 区切りが 1/3000[秒] より短くなる場合は、1/3000[秒] に引き上げます。`rate` が１より小さいときは、ＬＦＯクロックの１単位が整数個の区切りになるよう引き上げます。警告は出ません。

#### 【備考５】テンポが変わったとき

テンポが変わっても、いま進んでいる区切りは最後まで進み、次の区切りから新しい長さになります（区切りの途中で切り直すことはありません）。`@loc` / `@lor` を書いた場合は、その位置から新しい区切りで数え直します。
