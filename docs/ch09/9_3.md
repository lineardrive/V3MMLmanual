# 9.3 `@dlv[str],[str]`：配り方の切り替え（ポリフォニックモード）

[← 目次](../index.md)

## 【記述例】

```mml
#MB:ENV_A @ea=1 { peak=15, init=0 | n:1:15, r:4000:0 }
#MB:LFO_A @la=0 { depth=0, width=1, delay=0, form=pls_a }

@pl8,0 @ea1 @la0 @dlv"vl","all"
vl15 c1&vl10 c1&vl5 c1                      // タイで伸ばしている音の音量が、vl のたびにすぐ変わる
vl15 [c1&1&1 e1&1&1 g1&1&1 r1 vl10 r1 vl5]  // 和音を鳴らしている間に、vl のたびに音量がすぐ変わる
vl15 [c1 e1 g1] vl10 r1 vl5 r1              // 和音を鳴らし終えた後、リリース中の音の音量が、vl のたびにすぐ変わる
```

上記の場合、`@dlv"vl","all"` 記述以降の `vl` は、鳴っている音（タイで伸ばしている音、和音のゲート中の音、リリース中の音）にもすぐに効きます。  
（`r4000:0` のエンベロープの時間の単位は、`#MB:CONFIG` の `env_clock` で 1/1000 秒にしている前提です。）

和音を鳴らしている途中で値を変えるには、2 行目のように、大カッコの中で休符（`r`）を使って時刻を進め、その後にコマンドを書きます（[9.2](9_2.md)）。  
大カッコの中では、スラー（`&` の後に音符以外を続ける書き方）は使えません。`[c1&vl8 1 …]` はエラーになります。

## 【解説】

ポリフォニックモード（[9.1](9_1.md)）のトラックで、`v` や `@p` などのコマンドを、各発音チャネルへどのように配るかを切り替えます。

ポリフォニックモードでは、`v` や `@p` などの値は、いったん控えておき、次のノートオンの直前に、そのノートを鳴らす発音チャネルへ当てるのが通常の動きです（`seq`）。  
そのため、鳴っている音（ゲート中の音や、リリース中の音）には効きません。

`@dlv` で配り方を `all` にすると、以後のそのコマンドは、鳴っている音も含めて、すべての発音チャネルにすぐに当たります。

指定する引数は次の通りです。

- 引数[1]...宛先（ダブルクォートで括る）
- 引数[2]...配り方（ダブルクォートで括る）

引数はカンマで区切って指定します。

### 引数[1]（宛先）

配り方を切り替えるコマンドを、次の 8 つから 1 つ指定します。

|宛先|対象のコマンド|
|:-|:-|
|`"v"`|`v`（[4.9](../ch04/4_9.md)）と `)` `(`（[4.10](../ch04/4_10.md)）|
|`"vl"`|`vl`（[4.11](../ch04/4_11.md)）|
|`"mv"`|`mv`（[4.3](../ch04/4_3n4.md)）|
|`"@p"`|`@p`（[4.5](../ch04/4_5.md)）|
|`"p"`|`p`（[4.6](../ch04/4_6.md)）|
|`"px"`|`px`（[4.6.1](../ch04/4_6_1.md)）|
|`"vs"`|`vs`（[4.7](../ch04/4_7n8.md)）|
|`"ps"`|`ps`（[2.13](../ch02/2_13n14.md)）|

`)` `(` は計算した後の値を `v` として配るので、宛先 `"v"` に従います。  
ほかのコマンドは対象になりません。

### 引数[2]（配り方）

|配り方|動き|
|:-|:-|
|`"seq"`|値を控え、次のノートオンの直前に、その発音チャネルへ当てます（通常の動き。トラック先頭の状態）。|
|`"all"`|鳴っている音も含めて、すべての発音チャネルにすぐに当てます。|

- 宛先・配り方が上の表に無い場合（大文字の `"ALL"` など）や、文字列・カンマが欠けている場合はエラーになります。
- 切り替えは、その後に来るコマンドの配り方だけを変えます。切り替えた時点の値を配り直すことはしません。
- キーイベント（`@kt` `@kc` `@kl`。[10 章](../ch10/10_3n4.md)）が出したコマンドも、手で書いたコマンドと区別せず、その時点の配り方に従います。
- ポリフォニックモードではないトラック（単音のトラック）では、もともとすぐに効くので、何も起きません（エラーにもなりません）。

#### 【注意】`all` の動き

`all` は、通常は「鳴っている音の途中で値を変えない」作りになっている部分を、書き手の責任で動かす仕組みです。次の点に注意してください。

- `v`・`vl`・`mv`：音量が段差ですぐに変わります。プチッという音が出ることがあります。
- `vl` は、`@la` が掛かっていない発音チャネルには効きません（[4.11](../ch04/4_11.md) の注のとおり）。`depth=0` の `@la` を掛けておくと、`vl` だけを効かせられます（記述例）。
- `vf20,1` / `vf21,1`（[4.12](../ch04/4_12.md)）が効いている発音チャネルは、リリース中は今までどおり 1.0 倍のままです。
- `all` で配った `v`・`vl` は、各発音チャネルがその時点で持っている `vs` の目盛りで計算されます。  
`vl` を `all` で配るときは、`vs` も `all` にしてから `vs` を書いてください。`vs` が `seq` のままだと、まだ一度も鳴っていない発音チャネルは、最初のノートオンで `vs` を受け取って `vl` が最大値に戻り、先に配った `vl` が効きません（[4.7](../ch04/4_7n8.md)）。

```mml
@pl8,0 @dlv"vs","all" @dlv"vl","all" vs1 @la0 vl98   // vs を先に all にしておく
```

- `vs`：すべての発音チャネルの `vs` がすぐに替わり、`v`・`vl` は最大値に戻ります（[4.7](../ch04/4_7n8.md)）。鳴っている音は、その場で最大の音量になります。
- `ps`：曲の頭など、まだ何も鳴っていないときに、すべての発音チャネルへ同時に配るためのものです。  
鳴っている音（リリース中の音を含む）にも、すぐに当たります。その音の音程番号は前のピッチスケールで作られているので、ピッチＬＦＯなどで周波数を計算し直したときに、でたらめな周波数になります。  
曲の途中で使うときは、`z`（[7.8](../ch07/7_8.md)）で消音し、消え終わってから `ps` を書いてください。
- `@p`：パンの中心がすぐに動きます。`@lb` の揺れは、新しい中心の周りで続きます。
- `px`：波形の符号が途中で変わるので、クリック音が出やすくなります。
- キーイベントで音符ごとにパンなどを出している場合、その宛先を `all` にすると、鳴っているほかの音も動きます。
- 大カッコの中で音ごとに値を書き分けている場合（`[v3 c v8 e v13 g]` など）、その宛先を `all` にすると、同じ時刻に鳴り始めたほかの音にも次々に当たります。この例では、3 つの音がすべて `v13` になります。

#### 【表示】

ＭＭＬステータス表示（`!s`）には、`all` になっている宛先が `@dlv"vl","all"` のように表示されます。  
`!m` / `!d` の差分には、`seq` に戻したときも `@dlv"vl","seq"` と表示されます。  
KeyDisp には表示されません。
