# 3.3 `q%[1]`：ゲートタイム TYPE-2

[← 目次](../index.md)

## 【記述例】

```mml
#MB:CONFIG { tempo_unit: note_ticks=192: beat_length=4, }
@q0 q%40 c4 g2;
```

上記の場合、次のように演奏されます。

- `c` は 40ticks発音＋8ticks休符
- `g` は 40ticks発音＋56ticks休符

## 【解説】

ゲートタイムを、「ノートオンからの tickカウント数」で設定します。  
ある長さの音符を演奏するとき、実際に指定された音長のうち、何tickカウントを発音して残りを休符とするか、を決定します。用途は、スタッカートの表現などです。  
引数[1]には、発音する側の tickカウント数を 0 以上の整数で指定します。  
0 は本機能を無効にする特別な指定値です。  
トラック先頭における初期設定は、`q%0` です。

tickカウントあたりの発音長は、次の設定の影響を受けます。
```mml
#MB:CONFIG {
   tempo_unit: note_ticks=[]: beat_length=[],
}
```

### 【注】音長を超える指定値

引数[1]に、対象音符の音長を超える tickカウント数を指定した場合は、音長で頭打ちになります。  
例えば、音長が 192ticks の音符に対する `q%200` は、`q16,16`（音長いっぱい）と同等になります。

頭打ちは `@q`（ゲートタイム TYPE-3）で削る前に行われます。  
このため、`q%200 @q8` は「192ticks発音」ではなく「184ticks発音＋8ticks休符」になります。

### 【注】

本機能と `q`（ゲートタイム TYPE-1）は排他制御が掛かります。  
`q` を使いたい場合、本機能を `q%0` としてください。  
本機能と `@q`（ゲートタイム TYPE-3）は排他制御が掛からず、同時に作用します。
